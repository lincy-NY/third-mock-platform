## 1. 目标结构

> 变更记录：原方案为 server/web 两个独立 git 仓库；经用户确认调整为**单体 git 仓库**
> （远端 https://github.com/lincy-NY/third-mock-platform.git），模块目录划分不变。
> 目标结构中的目录布局维持如下，仅 git 归属变更为仓库根。

```

├── .agents/                    # AI 工作记录

├── third-mock-server/          # 仓库1：Go 服务端（含 CLI）
```

## 2. 静态资源双模式（两者兼容）

- 服务端启动配置新增 `web_dist`（外部目录，默认空）。
- 加载优先级：`web_dist` 目录存在且含 `index.html` → 使用外部目录（开发/热更新场景）；
  否则回退 `internal/static/dist` 的 go:embed 产物（单二进制部署场景）。
- `internal/static/dist/` 仅提交 `.keep` 占位（git 无法跟踪空目录，go:embed 要求目录非空）；
  真实产物经 `make embed-web` 覆盖写入且不纳入版本管理，发布后 git status 保持干净。

## 3. 构建发布链路

- `third-mock-web`：`npm run build` → `dist/`
- 聚合发布（工作区根 `make release`）：
  1. `cd third-mock-web && npm ci && npm run build`
  2. `rm -rf third-mock-server/internal/static/dist && cp -R third-mock-web/dist third-mock-server/internal/static/dist`
  3. `cd third-mock-server && make build-all`
- 服务端单独仓库也提供 `make embed-web WEB_DIST=../third-mock-web/dist` 完成第 2 步。

## 4. 前后端契约

- 管理 API 统一前缀 `/api/`（规则 CRUD、场景、请求记录查询、连通性测试等，随功能演进补充）。
- Vue dev 模式经 Vite proxy 转发 `/api` 到服务端管理端口，生产模式同源直接访问。
- CLI 留在服务端仓库，直接复用 internal/model，无跨仓库共享问题。

## 5. 风险与约束

- Node 18 环境 → Vite 锁 v5（Vite 6/7 需更高 Node）。
- 前端引入 node 工具链为用户明确决策，覆盖原「原生 H5 无构建」约定，AGENTS.md 同步修订。
- 红线：仅 `git init`，不执行 add/commit；`data/` 运行数据不迁移不删除。
